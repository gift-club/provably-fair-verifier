Як працює доказово чесний розіграш

Увесь алгоритм, із числами одного справжнього раунду, розібраного по кроках.

1. Зобов'язання: хеш серверного сида

Сервер обирає випадковий 32-байтний серверний сид і показує тобі лише його SHA-256 хеш. Хеш нічого не каже про сид, але фіксує його: в іншого сида такого хеша немає.

server seed      0f1e2d3c4b5a69788796a5b4c3d2e1f00112233445566778899aabbccddeeff0
SHA-256 (shown)  afa880ca0c7da502fc32ab284cf70852ef7c5540204e4215c2a1617074ca7905

2. Потік байтів: HMAC-SHA256

Ключ кожного раунду це сирий серверний сид, а повідомлення має вигляд clientSeed:nonce:round. Nonce рахує твої раунди на цій парі сидів; round рахує 32-байтні блоки, коли грі потрібно понад 32 байти.

key      = server seed (32 raw bytes)
message  = "gift-club-demo:0:0"        // clientSeed:nonce:round
block    = HMAC-SHA256(key, message)
bytes    = 1a bc a7 1f 1b 42 64 c5 …

3. Від байтів до чисел

Кожні чотири байти дають одне число з рухомою комою в [0, 1). Формула точна, тому верифікатор порівнює вихідне 32-бітне ціле, а не округлений десятковий дріб.

float = b0/256 + b1/256² + b2/256³ + b3/256⁴
      = 26/256 + 188/65536 + 167/16777216 + 31/4294967296
      = 0.1044411135

4. Від чисел до результату

Кожна гра перетворює числа на підсумок за власним опублікованим правилом: ряд відскоків уліво й управо в Плінко, перемішана колода в блекджеку, номер квитка в кейсі. Правила й таблиці виплат лежать в ігрових модулях у src/games/.

5. Округлення виплат

Виграш у зірках завжди ціле число. Якщо в ставки × множника є дробова частина, ще одне число вирішує, округлити вгору чи вниз, тож округлення теж доказово чесне. Виплати в Gram натомість округлюються вниз до нанотона й не витрачають число на округлення.

Версії таблиць виплат

Коли таблицю виплат перенастроюють, стара лишається в коді під своїм номером версії. Раунд завжди перевіряється за тією версією, на якій його зіграно; її показують деталі раунду.

Запусти тести сам

Набір тестів відтворює тисячі раундів, пораховані сервером, і звіряє кожен байт:

git clone https://github.com/gift-club/provably-fair-verifier.git
cd provably-fair-verifier && npm install && npm test

Запитання

Чому HMAC-SHA256, а не просто випадкове число?

Бо він детермінований: ті самі сиди й nonce завжди дають ті самі байти, тож результат можна перерахувати й перевірити. Звичайне випадкове число постфактум не перевірити.

Чи можуть ті самі сиди дати два результати?

Ні. Кожен раунд бере новий nonce, тому в двох раундів на одній парі сидів байти не збігаються.

Де лежать правила ігор?

У src/games/: один файл на гру, у кожному таблиці виплат, які використовує сервер.
