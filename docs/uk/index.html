Доказово чесний верифікатор

Перевір будь-який раунд Gift Club сам, на своєму комп'ютері, за тією самою математикою, що рахував сервер.

Доказово чесний раунд може перерахувати будь-хто. До раунду сервер публікує SHA-256 хеш секретного серверного сида, а після раунду відкриває сам сид. Цей пакет звіряє сид із хешем і заново розігрує раунд через HMAC-SHA256, тож видно: результат було визначено до твоєї гри й не змінено після неї.

Перевір раунд за чотири кроки

  1. У деталях раунду в Gift Club скопіюй хеш серверного сида, який показали до гри.
  2. Після зміни сида скопіюй відкритий серверний сид, свій клієнтський сид і nonce раунду.
  3. Запусти верифікатор: він перевірить, що SHA-256 від сида дорівнює хешу, і заново розіграє числа раунду.
  4. Порівняй перерахований результат із тим, що в твоїй історії. Вони збігаються байт у байт.

Як бібліотека

npm install @gift-club/provably-fair-verifier
import { generateFloats, hexToBytes, sha256Hex } from "@gift-club/provably-fair-verifier";

const seed = hexToBytes(serverSeed);
(await sha256Hex(seed)) === serverSeedHash;              // the seed was fixed before the round
const [f] = await generateFloats(seed, clientSeed, nonce, 1); // the round's first draw, in [0, 1)

Розіграш кожної гри (куди впаде кулька, які карти роздано, точка крашу) винесено в окремий простір імен, наприклад plinkoGold, crash або collect. Типи TypeScript у комплекті.

Кейси та скретч-карти

Кейси та скретч-карти розігруються за фіксованою таблицею квитків: верифікатор перераховує, який квиток випав, зокрема й за заданої цілі.

Зручніше в браузері? Встав ті самі значення в Перевірка provably fair: перевір раунд сам(а).

Чому коду можна довіряти

Кожна функція повторює серверний метод байт у байт, а тести прив'язують її до понад 2 600 пар вхід–вихід, отриманих кодом самого сервера. Якщо математика сервера зміниться, тести впадуть, доки верифікатор її не наздожене.

Запитання

Що означає «доказово чесно»?

Що будь-хто може довести: результат раунду було визначено до ставки й не змінено після. Сервер фіксує секретний сид, публікуючи його хеш, домішує сид, який задаєш ти, а свій сид відкриває пізніше, щоб ти міг перерахувати результат.

Чи може сервер змінити результат після моєї гри?

Лише так, щоб його впіймали: інший сид дає інший SHA-256 хеш, а хеш тобі показали до раунду.

Чому важливий мій клієнтський сид?

Результат залежить від обох сидів. Оскільки свій клієнтський сид можеш задати ти, сервер не може підібрати сид під наперед відомий підсумок.

Чи потрібні верифікатору інтернет або акаунт?

Ні. Він працює повністю на твоєму комп'ютері й потребує лише чотирьох значень із раунду.
