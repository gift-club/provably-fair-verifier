Jak działa losowanie Provably fair

Cały algorytm, z liczbami jednej prawdziwej rundy rozpisanymi krok po kroku.

1. Zobowiązanie: zahashowany server seed

Serwer wybiera losowy 32-bajtowy server seed i pokazuje ci tylko jego hash SHA-256. Hash nic nie zdradza o seedzie, ale go przypina: żaden inny seed nie ma takiego samego hasha.

server seed      0f1e2d3c4b5a69788796a5b4c3d2e1f00112233445566778899aabbccddeeff0
SHA-256 (shown)  afa880ca0c7da502fc32ab284cf70852ef7c5540204e4215c2a1617074ca7905

2. Strumień bajtów: HMAC-SHA256

Kluczem każdej rundy jest surowy server seed, a wiadomością clientSeed:nonce:round. Nonce liczy twoje rundy na tej parze seedów; round liczy 32-bajtowe bloki, gdy gra potrzebuje więcej niż 32 bajtów.

key      = server seed (32 raw bytes)
message  = "gift-club-demo:0:0"        // clientSeed:nonce:round
block    = HMAC-SHA256(key, message)
bytes    = 1a bc a7 1f 1b 42 64 c5 …

3. Od bajtów do liczb

Każde cztery bajty dają jeden float z przedziału [0, 1). Wzór jest dokładny, więc weryfikator porównuje leżącą pod spodem 32-bitową liczbę całkowitą, nigdy zaokrąglony ułamek dziesiętny.

float = b0/256 + b1/256² + b2/256³ + b3/256⁴
      = 26/256 + 188/65536 + 167/16777216 + 31/4294967296
      = 0.1044411135

4. Od liczb do wyniku

Każda gra zamienia floaty w wynik własną opublikowaną regułą: rząd odbić w lewo i w prawo w Plinko, potasowana talia w Blackjacku, numer biletu w skrzynce. Moduły gier w src/games/ zawierają każdą regułę i każdą tabelę wypłat.

5. Zaokrąglanie wypłat

Wygrana w Gwiazdkach jest liczbą całkowitą. Gdy stawka × mnożnik ma część ułamkową, jeszcze jeden float decyduje, czy zaokrąglić w górę, więc zaokrąglanie też jest Provably fair. Wypłaty w Gram są natomiast zaokrąglane w dół do nanotona i nie losują floata zaokrąglenia.

Wersje tabel wypłat

Gdy tabela wypłat jest przestrajana, stara zostaje w kodzie pod swoim numerem wersji. Rundę zawsze sprawdza się według wersji, na której ją rozegrano, co pokazują szczegóły rundy.

Uruchom testy u siebie

Zestaw testów odtwarza tysiące rund obliczonych przez serwer i sprawdza każdy bajt:

git clone https://github.com/gift-club/provably-fair-verifier.git
cd provably-fair-verifier && npm install && npm test

Pytania

Dlaczego HMAC-SHA256, a nie zwykła liczba losowa?

Bo jest deterministyczny: te same seedy i nonce zawsze dają te same bajty, więc wynik można przeliczyć i sprawdzić. Zwykłej liczby losowej nie da się sprawdzić po fakcie.

Czy te same seedy mogą dać dwa wyniki?

Nie. Każda runda używa nowego nonce, więc dwie rundy na jednej parze seedów nie mają wspólnych bajtów.

Gdzie są reguły gier?

W src/games/, po jednym pliku na grę, każdy z tabelami wypłat używanymi przez serwer.
