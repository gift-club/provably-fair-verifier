Как работает доказуемо честный розыгрыш

Весь алгоритм, с числами одного настоящего раунда, разобранного по шагам.

1. Обязательство: хеш серверного сида

Сервер выбирает случайный 32-байтный серверный сид и показывает тебе только его SHA-256 хеш. Хеш ничего не говорит о сиде, но фиксирует его: у другого сида такого же хеша нет.

server seed      0f1e2d3c4b5a69788796a5b4c3d2e1f00112233445566778899aabbccddeeff0
SHA-256 (shown)  afa880ca0c7da502fc32ab284cf70852ef7c5540204e4215c2a1617074ca7905

2. Поток байт: HMAC-SHA256

Ключ каждого раунда это сырой серверный сид, а сообщение имеет вид clientSeed:nonce:round. Nonce считает твои раунды на этой паре сидов; round считает 32-байтные блоки, когда игре нужно больше 32 байт.

key      = server seed (32 raw bytes)
message  = "gift-club-demo:0:0"        // clientSeed:nonce:round
block    = HMAC-SHA256(key, message)
bytes    = 1a bc a7 1f 1b 42 64 c5 …

3. От байт к числам

Каждые четыре байта дают одно число с плавающей точкой в [0, 1). Формула точная, поэтому верификатор сравнивает исходное 32-битное целое, а не округлённую десятичную дробь.

float = b0/256 + b1/256² + b2/256³ + b3/256⁴
      = 26/256 + 188/65536 + 167/16777216 + 31/4294967296
      = 0.1044411135

4. От чисел к результату

Каждая игра превращает числа в исход по собственному опубликованному правилу: ряд отскоков влево и вправо в Плинко, перемешанная колода в блэкджеке, номер билета в кейсе. Правила и таблицы выплат лежат в игровых модулях в src/games/.

5. Округление выплат

Выигрыш в звёздах всегда целое число. Если у ставки × множителя есть дробная часть, ещё одно число решает, округлить вверх или вниз, так что округление тоже доказуемо честное. Выплаты в Gram вместо этого округляются вниз до нанотона и не тратят число на округление.

Версии таблиц выплат

Когда таблицу выплат перенастраивают, старая остаётся в коде под своим номером версии. Раунд всегда проверяется по той версии, на которой он был сыгран; её показывают детали раунда.

Запусти тесты сам

Набор тестов воспроизводит тысячи раундов, посчитанных сервером, и сверяет каждый байт:

git clone https://github.com/gift-club/provably-fair-verifier.git
cd provably-fair-verifier && npm install && npm test

Вопросы

Почему HMAC-SHA256, а не просто случайное число?

Потому что он детерминированный: одни и те же сиды и nonce всегда дают одни и те же байты, поэтому результат можно пересчитать и проверить. Обычное случайное число после факта не проверить.

Могут ли одни и те же сиды дать два результата?

Нет. Каждый раунд берёт новый nonce, поэтому у двух раундов на одной паре сидов байты не совпадают.

Где лежат правила игр?

В src/games/: один файл на игру, в каждом таблицы выплат, которые использует сервер.
