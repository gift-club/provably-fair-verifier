Доказуемо честный верификатор

Проверь любой раунд Gift Club сам, на своём компьютере, по той же математике, что считал сервер.

Доказуемо честный раунд может пересчитать кто угодно. До раунда сервер публикует SHA-256 хеш секретного серверного сида, а после раунда открывает сам сид. Этот пакет сверяет сид с хешем и заново разыгрывает раунд через HMAC-SHA256, так что видно: результат был определён до твоей игры и не менялся после.

Проверь раунд за четыре шага

  1. В деталях раунда в Gift Club скопируй хеш серверного сида, который был показан до игры.
  2. После смены сида скопируй открытый серверный сид, свой клиентский сид и nonce раунда.
  3. Запусти верификатор: он проверит, что SHA-256 от сида равен хешу, и заново разыграет числа раунда.
  4. Сравни пересчитанный результат с тем, что в твоей истории. Они совпадают байт в байт.

Как библиотека

npm install @gift-club/provably-fair-verifier
import { generateFloats, hexToBytes, sha256Hex } from "@gift-club/provably-fair-verifier";

const seed = hexToBytes(serverSeed);
(await sha256Hex(seed)) === serverSeedHash;              // the seed was fixed before the round
const [f] = await generateFloats(seed, clientSeed, nonce, 1); // the round's first draw, in [0, 1)

Розыгрыш каждой игры (куда упадёт шарик, какие карты сданы, точка краша) вынесен в отдельное пространство имён, например plinkoGold, crash или collect. Типы TypeScript в комплекте.

Кейсы и скретч-карты

Кейсы и скретч-карты разыгрываются по фиксированной таблице билетов: верификатор пересчитывает, какой билет выпал, в том числе при заданной цели.

Удобнее в браузере? Вставь те же значения в Проверка provably fair: проверь раунд в браузере.

Почему коду можно доверять

Каждая функция повторяет серверный метод байт в байт, а тесты привязывают её к более чем 2 600 парам вход–выход, полученным кодом самого сервера. Если математика сервера изменится, тесты упадут, пока верификатор не догонит её.

Вопросы

Что значит «доказуемо честно»?

Что любой может доказать: результат раунда был определён до ставки и не менялся после. Сервер фиксирует секретный сид, публикуя его хеш, подмешивает сид, который задаёшь ты, а свой сид открывает позже, чтобы ты мог пересчитать результат.

Может ли сервер изменить результат после моей игры?

Только так, чтобы его поймали: другой сид даёт другой SHA-256 хеш, а хеш был показан тебе до раунда.

Почему важен мой клиентский сид?

Результат зависит от обоих сидов. Раз свой клиентский сид можешь задать ты, сервер не может подобрать сид под заранее известный исход.

Нужен ли верификатору интернет или аккаунт?

Нет. Он работает целиком на твоём компьютере и требует только четыре значения из раунда.
