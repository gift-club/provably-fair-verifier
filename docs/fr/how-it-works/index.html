Comment fonctionne le tirage Provably fair

Tout l'algorithme, avec les nombres d'une vraie manche d'exemple déroulés pas à pas.

1. L'engagement : un server seed haché

Le serveur choisit un server seed aléatoire de 32 octets et ne te montre que son hash SHA-256. Le hash ne révèle rien du seed, mais il le fige : aucun autre seed n'a le même hash.

server seed      0f1e2d3c4b5a69788796a5b4c3d2e1f00112233445566778899aabbccddeeff0
SHA-256 (shown)  afa880ca0c7da502fc32ab284cf70852ef7c5540204e4215c2a1617074ca7905

2. Le flux d'octets : HMAC-SHA256

Chaque manche utilise le server seed brut comme clé et clientSeed:nonce:round comme message. Le nonce compte tes manches sur cette paire de seeds ; round compte les blocs de 32 octets quand un jeu a besoin de plus de 32 octets.

key      = server seed (32 raw bytes)
message  = "gift-club-demo:0:0"        // clientSeed:nonce:round
block    = HMAC-SHA256(key, message)
bytes    = 1a bc a7 1f 1b 42 64 c5 …

3. Des octets aux nombres

Chaque groupe de quatre octets donne un float dans [0, 1). La formule est exacte : le vérificateur compare donc l'entier 32 bits sous-jacent, jamais une décimale arrondie.

float = b0/256 + b1/256² + b2/256³ + b3/256⁴
      = 26/256 + 188/65536 + 167/16777216 + 31/4294967296
      = 0.1044411135

4. Des nombres à un résultat

Chaque jeu transforme ses floats en résultat selon sa propre règle publiée : une suite de rebonds à gauche et à droite au Plinko, un paquet mélangé au Blackjack, un numéro de ticket dans un coffre. Les modules de jeu dans src/games/ contiennent chaque règle et chaque table de gains.

5. Arrondi du gain

Un gain en Étoiles est un nombre entier. Quand mise × multiplicateur a une partie décimale, un float de plus décide s'il faut arrondir vers le haut, donc l'arrondi est lui aussi Provably fair. Les gains en Gram sont en revanche arrondis vers le bas au nanoton et ne tirent aucun float d'arrondi.

Versions des tables de gains

Quand une table de gains est réajustée, l'ancienne reste dans le code sous son numéro de version. Une manche est toujours vérifiée selon la version sur laquelle elle a été jouée, qu'indiquent les détails de la manche.

Lance les tests toi-même

La suite de tests rejoue des milliers de manches calculées par le serveur et vérifie chaque octet :

git clone https://github.com/gift-club/provably-fair-verifier.git
cd provably-fair-verifier && npm install && npm test

Questions

Pourquoi HMAC-SHA256 et pas un simple nombre aléatoire ?

Parce qu'il est déterministe : les mêmes seeds et le même nonce donnent toujours les mêmes octets, donc un résultat peut être recalculé et vérifié. Un simple nombre aléatoire ne peut pas être vérifié après coup.

Les mêmes seeds peuvent-ils produire deux résultats ?

Non. Chaque manche utilise un nouveau nonce, donc deux manches sur une même paire de seeds ne partagent pas leurs octets.

Où sont les règles des jeux ?

Dans src/games/, un fichier par jeu, chacun avec les tables de gains que le serveur utilise.
