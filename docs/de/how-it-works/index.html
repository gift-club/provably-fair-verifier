So funktioniert die Provably-fair-Ziehung

Der ganze Algorithmus, mit den Zahlen einer echten Beispielrunde durchgerechnet.

1. Die Festlegung: ein gehashter Server Seed

Der Server wählt einen zufälligen 32-Byte-Server Seed und zeigt dir nur dessen SHA-256-Hash. Der Hash verrät nichts über den Seed, legt ihn aber fest: Kein anderer Seed hat denselben Hash.

server seed      0f1e2d3c4b5a69788796a5b4c3d2e1f00112233445566778899aabbccddeeff0
SHA-256 (shown)  afa880ca0c7da502fc32ab284cf70852ef7c5540204e4215c2a1617074ca7905

2. Der Bytestrom: HMAC-SHA256

Jede Runde nutzt den rohen Server Seed als Schlüssel und clientSeed:nonce:round als Nachricht. Der Nonce zählt deine Runden mit diesem Seed-Paar; round zählt 32-Byte-Blöcke, wenn ein Spiel mehr als 32 Bytes braucht.

key      = server seed (32 raw bytes)
message  = "gift-club-demo:0:0"        // clientSeed:nonce:round
block    = HMAC-SHA256(key, message)
bytes    = 1a bc a7 1f 1b 42 64 c5 …

3. Von Bytes zu Zahlen

Je vier Bytes ergeben einen Float in [0, 1). Die Formel ist exakt, deshalb vergleicht der Verifier die zugrunde liegende 32-Bit-Ganzzahl, nie eine gerundete Dezimalzahl.

float = b0/256 + b1/256² + b2/256³ + b3/256⁴
      = 26/256 + 188/65536 + 167/16777216 + 31/4294967296
      = 0.1044411135

4. Von Zahlen zu einem Ergebnis

Jedes Spiel macht aus seinen Floats ein Ergebnis nach einer eigenen veröffentlichten Regel: eine Reihe von Links-rechts-Abprallern bei Plinko, ein gemischtes Deck bei Blackjack, eine Ticketnummer in einer Box. Die Spielmodule in src/games/ enthalten jede Regel und jede Auszahlungstabelle.

5. Auszahlungsrundung

Ein Gewinn in Sternen ist eine ganze Zahl. Hat Einsatz × Multiplikator einen Nachkommaanteil, entscheidet ein weiterer Float, ob aufgerundet wird, sodass auch die Rundung Provably fair ist. Gram-Auszahlungen werden stattdessen auf den Nanoton abgerundet und ziehen keinen Rundungs-Float.

Versionen der Auszahlungstabelle

Wird eine Auszahlungstabelle neu abgestimmt, bleibt die alte unter ihrer Versionsnummer im Code. Eine Runde wird immer gegen die Version geprüft, auf der sie gespielt wurde; sie steht in den Rundendetails.

Die Tests selbst ausführen

Die Testsuite spielt Tausende vom Server berechnete Runden nach und prüft jedes Byte:

git clone https://github.com/gift-club/provably-fair-verifier.git
cd provably-fair-verifier && npm install && npm test

Fragen

Warum HMAC-SHA256 und keine normale Zufallszahl?

Weil es deterministisch ist: Dieselben Seeds und derselbe Nonce ergeben immer dieselben Bytes, deshalb lässt sich ein Ergebnis neu berechnen und prüfen. Eine normale Zufallszahl lässt sich im Nachhinein nicht prüfen.

Können dieselben Seeds zwei Ergebnisse erzeugen?

Nein. Jede Runde nutzt einen neuen Nonce, daher teilen zwei Runden auf einem Seed-Paar nie ihre Bytes.

Wo stehen die Spielregeln?

In src/games/, eine Datei pro Spiel, jede mit den Auszahlungstabellen, die der Server nutzt.
