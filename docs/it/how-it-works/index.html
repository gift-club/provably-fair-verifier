Come funziona l'estrazione Provably fair

L'intero algoritmo, con i numeri di un round reale svolti passo passo.

1. L'impegno: un server seed con hash

Il server sceglie un server seed casuale di 32 byte e ti mostra solo il suo hash SHA-256. L'hash non rivela nulla del seed, ma lo fissa: nessun altro seed ha lo stesso hash.

server seed      0f1e2d3c4b5a69788796a5b4c3d2e1f00112233445566778899aabbccddeeff0
SHA-256 (shown)  afa880ca0c7da502fc32ab284cf70852ef7c5540204e4215c2a1617074ca7905

2. Il flusso di byte: HMAC-SHA256

Ogni round usa come chiave il server seed grezzo e come messaggio clientSeed:nonce:round. Il nonce conta i tuoi round su questa coppia di seed; round conta i blocchi da 32 byte quando un gioco ha bisogno di più di 32 byte.

key      = server seed (32 raw bytes)
message  = "gift-club-demo:0:0"        // clientSeed:nonce:round
block    = HMAC-SHA256(key, message)
bytes    = 1a bc a7 1f 1b 42 64 c5 …

3. Dai byte ai numeri

Ogni quattro byte formano un float in [0, 1). La formula è esatta, quindi il verificatore confronta l'intero a 32 bit sottostante, mai un decimale arrotondato.

float = b0/256 + b1/256² + b2/256³ + b3/256⁴
      = 26/256 + 188/65536 + 167/16777216 + 31/4294967296
      = 0.1044411135

4. Dai numeri a un risultato

Ogni gioco trasforma i suoi float in un esito con una regola propria e pubblicata: una fila di rimbalzi a sinistra e a destra in Plinko, un mazzo mescolato nel Blackjack, un numero di biglietto in una cassa. I moduli dei giochi in src/games/ contengono ogni regola e ogni tabella dei pagamenti.

5. Arrotondamento della vincita

Una vincita in Stelle è un numero intero. Quando puntata × moltiplicatore ha una parte frazionaria, un altro float decide se arrotondare per eccesso, quindi anche l'arrotondamento è Provably fair. I pagamenti in Gram, invece, sono arrotondati per difetto al nanoton e non estraggono nessun float di arrotondamento.

Versioni della tabella dei pagamenti

Quando una tabella dei pagamenti viene ritarata, quella vecchia resta nel codice con il suo numero di versione. Un round viene sempre verificato con la versione su cui è stato giocato, indicata nei dettagli del round.

Esegui i test in autonomia

La suite di test riproduce migliaia di round calcolati dal server e controlla ogni byte:

git clone https://github.com/gift-club/provably-fair-verifier.git
cd provably-fair-verifier && npm install && npm test

Domande

Perché HMAC-SHA256 e non un semplice numero casuale?

Perché è deterministico: gli stessi seed e lo stesso nonce danno sempre gli stessi byte, quindi un risultato si può ricalcolare e controllare. Un semplice numero casuale non si può controllare a posteriori.

Gli stessi seed possono produrre due risultati?

No. Ogni round usa un nonce nuovo, quindi due round sulla stessa coppia di seed non condividono i loro byte.

Dove sono le regole dei giochi?

In src/games/, un file per gioco, ognuno con le tabelle dei pagamenti che usa il server.
