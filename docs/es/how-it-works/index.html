Cómo funciona el sorteo Provably fair

El algoritmo completo, con los números de una ronda real resuelta paso a paso.

1. El compromiso: un server seed con hash

El servidor elige un server seed aleatorio de 32 bytes y te muestra solo su hash SHA-256. El hash no revela nada del seed, pero lo fija: ningún otro seed tiene el mismo hash.

server seed      0f1e2d3c4b5a69788796a5b4c3d2e1f00112233445566778899aabbccddeeff0
SHA-256 (shown)  afa880ca0c7da502fc32ab284cf70852ef7c5540204e4215c2a1617074ca7905

2. El flujo de bytes: HMAC-SHA256

Cada ronda usa como clave el server seed en bruto y como mensaje clientSeed:nonce:round. El nonce cuenta tus rondas con este par de seeds; round cuenta bloques de 32 bytes cuando un juego necesita más de 32 bytes.

key      = server seed (32 raw bytes)
message  = "gift-club-demo:0:0"        // clientSeed:nonce:round
block    = HMAC-SHA256(key, message)
bytes    = 1a bc a7 1f 1b 42 64 c5 …

3. De bytes a números

Cada cuatro bytes forman un float en [0, 1). La fórmula es exacta, así que el verificador compara el entero de 32 bits subyacente, nunca un decimal redondeado.

float = b0/256 + b1/256² + b2/256³ + b3/256⁴
      = 26/256 + 188/65536 + 167/16777216 + 31/4294967296
      = 0.1044411135

4. De números a un resultado

Cada juego convierte sus floats en un resultado con su propia regla publicada: una fila de rebotes a izquierda y derecha en Plinko, una baraja mezclada en Blackjack, un número de boleto en una caja. Los módulos de juego en src/games/ contienen cada regla y cada tabla de pagos.

5. Redondeo del pago

Un premio en Estrellas es un número entero. Cuando apuesta × multiplicador tiene fracción, un float más decide si se redondea hacia arriba, así que el redondeo también es Provably fair. Los pagos en Gram, en cambio, se redondean hacia abajo al nanoton y no sortean ningún float de redondeo.

Versiones de la tabla de pagos

Cuando se reajusta una tabla de pagos, la antigua se queda en el código con su número de versión. Una ronda siempre se comprueba con la versión con la que se jugó, que aparece en los detalles de la ronda.

Preguntas

¿Por qué HMAC-SHA256 y no un número aleatorio normal?

Porque es determinista: los mismos seeds y el mismo nonce dan siempre los mismos bytes, así que un resultado se puede recalcular y comprobar. Un número aleatorio normal no se puede comprobar a posteriori.

¿Pueden los mismos seeds producir dos resultados?

No. Cada ronda usa un nonce nuevo, así que dos rondas con el mismo par de seeds nunca comparten bytes.

¿Dónde están las reglas de los juegos?

En src/games/, un archivo por juego, cada uno con las tablas de pagos que usa el servidor.
